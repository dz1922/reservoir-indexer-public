# Digital Culture Data Layer — 愿景与策略

## 一句话

**让 AI Agent 自由理解、分析和操作数字文化资产市场数据的基础设施。**

## 问题

数字文化资产——NFT、游戏道具、虚拟物品、实体收藏品、艺术品——分散在数十个平台上交易。目前不存在一个数据层能够：

1. 跨资产类型聚合和标准化数据
2. 以 AI Agent 而非人类为主要消费者来设计
3. 提供加工过的、结构化的、带上下文的数据（而不只是原始交易）

2025 年，最好的两个 NFT 数据服务（Reservoir、SimpleHash）相继关闭。剩下的只有原始数据转储，没有智能层。市场需要的是基础设施，不是又一个 dashboard。

## 核心判断

**做基础设施，不做应用。** 我们构建数据层，其他人（包括 AI Agent）在上面构建应用。

**AI-Native，不是 AI 附加。** MCP 是主接口。每个 API 响应都为 Agent 消费而设计——自描述、带上下文、可直接行动。REST 是给开发者的次要接口。

**先深后广。** 从一个资产类别做到最深（CryptoPunks），验证模型可行，再横向扩展。

## 三根支柱

### 1. 数据基础设施服务

我们不是产品，我们是基础设施。

- **完整数据**：每笔交易、每个出价、每次所有权变更，不留空白
- **加工数据**：不是原始事件——而是结构化的历史、持有者画像、市场深度、休眠分析
- **可靠数据**：链重组检测、区块间隙补全、洗盘交易标记，数据完整性不可妥协
- **可扩展数据**：新增一个资产类别 = 新增一个数据适配器，不是重建系统

### 2. AI-Native、Agent-Facing

这个服务的主要用户不是人，是 AI Agent。

- **MCP 优先**：Agent 通过 Model Context Protocol 连接，每次数据查询就是一次 tool call
- **自描述响应**：每个响应都包含"这是什么数据"、"意味着什么"、"有什么值得注意的"
- **聚合查询**：一次 tool call 回答一个问题。Agent 问"这个 Punk 值得买吗？"，一次调用拿到价格历史、可比交易、出价深度、持有者画像——不需要 5 次 API 调用
- **不做 dashboard**：我们不做 UI，不做图表。Agent 就是 UI

### 3. 先深后广的扩展路径

```
Phase 1: CryptoPunks（Crypto — NFT）
   │      完美的第一个数据集：
   │      - 100% 链上数据，不依赖中心化 API
   │      - 10 年交易历史，链上最丰富的数据集
   │      - 最高的文化认知度
   │      - 规模可控（10,000 个）
   │
Phase 2: 扩展到更多 NFT
   │      Art Blocks, Autoglyphs, Pudgy Penguins...
   │      同一套基础设施，新的数据适配器
   │
Phase 3: 数字收藏品
   │      游戏道具（CS2 皮肤、Fortnite 物品）
   │      虚拟物品、链游资产
   │      新的数据源适配器（非区块链）
   │
Phase 4: 实体收藏品与艺术品
          交易卡牌（Pokémon、球星卡）
          带数字溯源的实体艺术品
          奢侈品认证
```

## 我们构建的是一个框架

**核心原则：我们不为任何一个 collection 做定制化开发。我们构建一个框架，CryptoPunks 是跑在框架上的第一个实例。**

### 框架 vs 定制化的区别

| 定制化做法（不要） | 框架做法（我们的方式） |
|------------------|---------------------|
| `get_punk_history` | `get_item_history({ collection, tokenId })` |
| CryptoPunks 专属的 holder 分类逻辑 | 通用的 holder 行为分析引擎，输入是标准化事件流 |
| Stash Factory 硬编码为核心模块 | Stash 作为 CryptoPunks adapter 的一个数据源插件 |
| 为 CryptoPunks 定制 wash trade 规则 | 通用 wash trade 检测算法，接受任意交易流 |
| 每个 collection 一套 API | 一套 API，collection 是参数 |

### 新增一个 Collection 需要做什么

理想状态下，新增一个 collection 只需要：

1. **写一个数据适配器**：告诉框架去哪里拿数据、怎么解析成标准 Event
2. **配置文件加一行**：合约地址或数据源 URL
3. **完成**：所有通用能力自动可用（历史、画像、休眠、洗盘、市场深度）

不需要写新 API、不需要写新分析逻辑、不需要改框架代码。

## Phase 1：提供数据原语，让 Agent 自由组合

第一个版本我们不做复杂的衍生分析（持有者画像、洗盘检测等），而是提供**干净、完整、结构化的基础市场数据**：

- **Sales** — 成交记录
- **Bids** — 出价/报价
- **Listings** — 在售挂单
- **Transfers** — 所有权变更
- **Floor Price** — 地板价
- **Metadata** — 资产属性和图片

这些是数据原语。Agent 拿到这些原语之后，可以自己组合分析：

- "这个 Punk 最近 3 个月成交了几次？" → Agent 组合 sales + 时间过滤
- "谁在大量买入？" → Agent 组合 transfers + 钱包聚合
- "地板价在涨还是跌？" → Agent 组合 floor price + 时间序列
- "这个 Punk 合理估值是多少？" → Agent 组合 sales + attributes + 可比分析

**我们不预设问题，我们提供回答任何问题的原材料。** AI 的强项就是从原始数据中提取洞察，我们不需要替它做这件事。

复杂的衍生分析（holder profiling、dormancy、wash trade detection）作为后续版本逐步加入——当我们发现 Agent 反复在做同样的计算时，就把它下沉到基础设施层。

## CryptoPunks 作为第一个场景

CryptoPunks 不是产品，是**验证框架的第一个测试用例**。

选择它的理由：

| 理由 | 说明 |
|------|------|
| 数据完全在链上 | 不依赖任何可能关闭的中心化 API |
| 10 年历史 | 链上最丰富的 NFT 数据集 |
| 复杂度够高 | 5 个合约、内置市场、wrap/unwrap、stash bid——如果框架能处理这个，就能处理任何东西 |
| 规模可控 | 只有 10,000 个，完整索引可行 |
| 市场空白 | Reservoir 关闭后无替代品，有即时需求 |
| 文化认知度最高 | AI Agent 被问到的概率最大 |

CryptoPunks 的具体数据源（5 个合约）和衍生数据（持有者画像、休眠分析等）都是**通过框架的通用能力实现的**，不是 CryptoPunks 专属代码。
